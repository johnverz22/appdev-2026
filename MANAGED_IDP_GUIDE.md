# Guide: Offloading Authentication to Firebase (Managed IdP)

Using a Managed Identity Provider (IdP) like **Firebase Authentication** replaces the need for custom auth logic, localized database user management, and manually signed JWTs. Instead of building and maintaining a custom Spring Boot Auth service, Firebase securely handles logins, issues standard JWT tokens, and our API Gateway validates those tokens cryptographically.

## Overview of the New Architecture
1. **Frontend (React)** handles authentication directly with Firebase via the Firebase SDK.
2. User authenticates via Email/Password or **Google Sign-In** within the frontend popup.
3. Firebase returns a secure Access Token (ID Token) to the frontend.
4. The frontend passes this token to the **API Gateway** inside an `Authorization: Bearer <token>` header on every request.
5. The API Gateway validates the token using Firebase's public keys natively, extracts the user properties (like UID or Email), and injects them into downstream request headers (`X-User-Name`).
6. **Result**: The entire local `sb/` (Spring Boot Authentication) service can be **deleted**, as registration, login, token issuance, and password resets are purely managed by Firebase.

---

## Step 1: Configure Firebase
1. Go to the [Firebase Console](https://console.firebase.google.com/) and create a new project (e.g., `microservices-auth`).
2. Navigate to **Authentication** -> **Sign-in method**.
3. Enable **Email/Password**.
4. Enable **Google** (This automatically provisions the required OAuth credentials under the hood).
5. Go to **Project Settings** -> **General** and register a "Web App" to get your Firebase configuration keys `firebaseConfig` (API Key, Auth Domain, Project ID, etc.).

---

## Step 2: Implement Frontend Login and Google Sign-in
Replace the custom React login page and manual backend API calls with the official Firebase SDK.

```bash
npm install firebase
```

Initialize Firebase in your React app (e.g., `firebase.js`):
```javascript
import { initializeApp } from "firebase/app";
import { getAuth, GoogleAuthProvider } from "firebase/auth";

const firebaseConfig = {
  apiKey: "YOUR_API_KEY",
  authDomain: "YOUR_PROJECT_ID.firebaseapp.com",
  projectId: "YOUR_PROJECT_ID",
  // ...other config
};

const app = initializeApp(firebaseConfig);
export const auth = getAuth(app);
export const googleProvider = new GoogleAuthProvider();
```

Implement the Login functions in your React component:
```jsx
import { signInWithEmailAndPassword, signInWithPopup } from 'firebase/auth';
import { auth, googleProvider } from './firebase';

// Option 1: Standard Email Login
const handleEmailLogin = async (email, password) => {
    const userCredential = await signInWithEmailAndPassword(auth, email, password);
    const token = await userCredential.user.getIdToken();
    return token;
};

// Option 2: Google Sign-In
const handleGoogleLogin = async () => {
    const userCredential = await signInWithPopup(auth, googleProvider);
    const token = await userCredential.user.getIdToken();
    return token;
};
```

When interacting with your backend microservices (like PHP or Django), fetch the Firebase token and append it to the Auth header:
```javascript
import { auth } from './firebase';

const fetchProducts = async () => {
    // Force refresh or get current token
    const token = await auth.currentUser.getIdToken(); 
    
    fetch('http://localhost:8000/api/products', {
      headers: { Authorization: `Bearer ${token}` }
    });
}
```

## Step 3: Refactor the API Gateway into a Resource Server
Your API Gateway currently validates an internal cookie generated by the `sb/` backend. Now, we configure it to validate Firebase JWTs natively using Spring Security.

1. In `api-gateway/pom.xml`, add the OAuth2 Resource Server dependency:
   ```xml
   <dependency>
       <groupId>org.springframework.boot</groupId>
       <artifactId>spring-boot-starter-oauth2-resource-server</artifactId>
   </dependency>
   ```

2. Update `api-gateway/src/main/resources/application.yml`. **Firebase is fully compatible with standard OAuth2 resource servers**—you just need to provide your Project ID!
   ```yaml
   spring:
     security:
       oauth2:
         resourceserver:
           jwt:
             issuer-uri: https://securetoken.google.com/YOUR_FIREBASE_PROJECT_ID
             # Spring automatically downloads Firebase's public keys to verify the signature!
   ```

3. Update the Gateway Security Config. Remove the custom `JwtAuthFilter` Java class completely. Configure the Gateway to act as an OAuth2 JWT receiver:
   ```java
   @Bean
   public SecurityWebFilterChain securityWebFilterChain(ServerHttpSecurity http) {
       http
           .authorizeExchange(exchanges -> exchanges
               .pathMatchers("/api/public/**").permitAll()
               .anyExchange().authenticated()
           )
           .oauth2ResourceServer(oauth2 -> oauth2.jwt());
       return http.build();
   }
   ```

4. **Ensure Downstream Trust**: Downstream services (PHP, Django) rely on the `X-User-Name` header to identify users. Create a Spring Cloud `GlobalFilter` in the Gateway that extracts the standard `sub` (Firebase UID) or `email` claim from the validated OAuth2 JWT and dynamically sticks it into the `X-User-Name` header before routing the traffic. *(If your Django/PHP apps rely on user roles, you can assign them in Firebase using "Custom Claims").*

---

## Step 4: Decommission the `sb/` Service
Since Firebase handles the User Registration pages, Logins, Password resets, user blocking, and profile database storage natively, the local `sb/` service is no longer strictly required.

1. Stop the application.
2. Remove the `sb` service definition from `docker-compose.yml`.
3. Drop the PostgreSQL `users` table since user data is securely managed by Firebase Identity. Django and PHP will now bind their data rows (e.g., `orders`) to the User's unique Firebase UID or Email instead of a custom numerical backend ID.
